## Objective

Establish secure, resilient database connection management and kernel-enforced containment for the analytics query execution engine. Configure bounded connection pools, deterministic statement and lock timeouts, asynchronous transaction cancellation via PostgreSQL backend PID signaling, and rigorous automated stress tests validating that resource exhaustion, runaway queries, and privilege escalation attempts fail safely without impacting database availability.

- **Status:** ⚪ PLANNED
- **Target Artifacts:** `backend/src/config/env.ts`, `backend/src/database/analytics-pool.ts`
- **Checklist:**
  - [ ] Configure environment variables for dedicated analytics pool:
    - `ANALYTICS_DB_POOL_MAX`: `10` (maximum physical connections)
    - `ANALYTICS_DB_POOL_MIN`: `2` (minimum idle connections)
    - `ANALYTICS_DB_CONNECTION_TIMEOUT_MS`: `3000` (connection acquire deadline)

    - `ANALYTICS_LOCK_TIMEOUT_MS`: `1000` (lock acquisition deadline)
  - [ ] Enforce session-level PostgreSQL GUCs on every connection checkout:
    ```sql
    SET default_transaction_read_only = on;
    SET statement_timeout = '5000ms';
    SET lock_timeout = '1000ms';
    SET idle_in_transaction_session_timeout = '10000ms';
    ```
  - [ ] Validate that connection pool rejects requests when saturated rather than queuing indefinitely.
- **Done When:** Dedicated analytics connection pool boots with verified pool bounds and kernel timeouts.
