## Objective

Provision separate database roles (`analytics_user`, `app_user`, `db_migrator`), establish isolated logical databases (`analytics_db`, `app_db`), and provide automated privilege-denial verification proving analytical queries cannot write or access application metadata.

---

### [ ] Task 1: Multi-Database Container Configuration
- **Status:** ⚪ PENDING
- **Target Artifacts:** `infra/compose/compose.yaml`, `infra/compose/init-scripts/`
- **Checklist:**
  - [ ] Configure PostgreSQL 16 container bound to isolated loopback `127.0.0.1:5434:5432`.

### [ ] Task 2: Dedicated SQL Roles & Kernel Permission Containment
- **Status:** ⚪ PENDING
- **Target Artifacts:** `database/roles/01-roles.sql`
- **Checklist:**
  - [ ] Define `analytics_user` with read-only permissions on `analytics_db` and transaction read-only flag.
  - [ ] Define `app_user` with CRUD permissions on `app_db` and zero permissions on `analytics_db`.
  - [ ] Restrict connection permissions: `analytics_user` cannot connect to `app_db`.
  - [ ] Restrict administrative permissions: neither role can alter schemas, execute administrative functions, or create temporary tables.
- **Done When:** Roles are applied and verified against PostgreSQL's `pg_roles` and `pg_database` access tables.
