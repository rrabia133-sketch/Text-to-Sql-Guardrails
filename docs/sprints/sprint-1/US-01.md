## Story Narrative

> **As a developer**,  
> **I want** empirical feasibility evidence for AST SQL parsing, database role containment, and model performance,  
> **So that** subsequent application development starts with proven safety boundaries and viable model choices.

---

## Acceptance Criteria

- [ ] **AC-1 (Parser Traversal):** Given candidate parser (`pgsql-ast-parser` or WASM `libpg-query`), adversarial and supported SQL cases produce recorded expected allow/reject outcomes with recursive AST node inspection.
- [ ] **AC-2 (Database Containment):** Given the analytics database credential, execution directly against PostgreSQL succeeds for permitted SELECTs and is unconditionally rejected for writes, schema changes, temporary objects, and privilege escalation.
- [ ] **AC-3 (Provider Benchmarking):** Given available workstation hardware and cloud quotas, local Ollama (`qwen2.5-coder:7b`) and cloud Groq models are benchmarked for accuracy, speed, VRAM/memory use, and cost per query under an enforced spending cap.
- [ ] **AC-4 (Decision Records):** Architectural decision records (ADRs) document the supported SQL subset, selected parser, provider policies, and containment model before any product UI or execution API code is written.
